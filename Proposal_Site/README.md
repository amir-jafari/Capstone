# GWU Data Science Capstone Proposals — website

A Streamlit site for the capstone proposals in `Report_Gen/Arxiv/`.

| Page | Who | What |
|---|---|---|
| **Proposals** (home) | everyone | Landing page, stats, search, year/semester/source filters, topic chips, cards grouped by semester, full proposal view with figure and HTML/Markdown/JSON downloads |
| **Propose a project** | everyone | Form with the same fields as `Report_Gen/json_gen.py`; saves to `Report_Gen/Arxiv/External/` |
| **Check submission** | everyone | Pick semester + number → status, public reviewer comments; submitter edits & resubmits after confirming their email |
| **Reviewer** | you (password) | Review queue, approve / request changes / reject, comments (public or internal), promote to official, delete spam |

## Folder layout (same structure as Report_Gen)

```
Report_Gen/Arxiv/
├── Proposals/{Year}/{Semester}/{N}/     # yours — produced by Report_Gen as before
│     input.json  proposal_N.md  proposal_N.html  {Year}_{Semester}_{N}.png
└── External/{Year}/{Semester}/{N}/      # submitted through the website
      input.json  proposal_N.md  proposal_N.html  [{Year}_{Semester}_{N}.png]  review.json
```

`proposal_N.md/html` for outside submissions are generated by `Report_Gen/script.py`
itself (`generate_readme` + `convert_md_to_html`), so they match yours exactly.
`review.json` holds the status (`pending`, `changes_requested`, `approved`, `rejected`),
and the review history.

**Promote** (admin, approved items only) copies a community proposal into
`Proposals/{Year}/{Semester}/{next N}/` with the version renumbered.

Nothing in `Report_Gen/` changed — keep making proposals exactly as before; the site
picks up every folder automatically.

## Run locally

```bash
cd Proposal_Site
pip install -r requirements.txt
cp .streamlit/secrets.toml.example .streamlit/secrets.toml   # set admin password
streamlit run streamlit_app.py
```

Without a `[github]` token the site reads and writes the local checkout. Commit and push yourself.

## Deploy on Streamlit Community Cloud

1. Push this repo to GitHub.
2. Go to <https://share.streamlit.io> → **Create app** → repo `amir-jafari/Capstone`, branch `main`,
   main file `Proposal_Site/streamlit_app.py`.
3. Create a **fine-grained personal access token** (GitHub → Settings → Developer settings):
   repository access *only* `amir-jafari/Capstone`, permission **Contents: Read and write**.
4. In the app's **Settings → Secrets**, paste the contents of `.streamlit/secrets.toml.example`
   with your real password and token.

With the token set, every submission, review, promotion, and deletion is **one git commit**
on `main` (via the GitHub Git Data API), so your repo is always the source of truth. Streamlit
Cloud also redeploys when the repo changes, so the app may restart briefly after a write.

## Notes

- Submitter names/emails are stored in the (public) repo, same as existing proposals — the form says so.
- Internal (non-public) reviewer comments are hidden on the site but still live in `review.json` in the repo.
- Basic spam protection: field validation, hidden honeypot field, 5 MB image limit. Use **Delete** for spam.
- Topic chips are keyword-based (`core/catalog.py → TOPICS`); edit the regexes to tune them.
